A PDF file can carry JavaScript in four different places, and each of them runs at a different moment. The document below has all of them, and every script writes one line into the log field - so you can watch the order of events as it happens.

WhereWhen it runs
/Names /JavaScriptdocument-level script, when the file is opened
/OpenActionwhen the file is opened
/AA in the catalogWillPrint, DidPrint, WillSave, DidSave, WillClose*
/AA on a pagePageOpen, PageClose - scroll to page 2

These two flags decide which of them ngx-extended-pdf-viewer lets through:

  • enableCatalogAAJavaScript - the additional actions of the catalog. Printing triggers WillPrint and DidPrint, the download button triggers WillSave and DidSave. Switch the flag off and the log stays empty for those events, because the library strips the scripts out of the catalog before pdf.js ever sees them.
    *WillClose is the exception: the script is in the file and pdf.js hands it to the sandbox, but you never see it run. When the viewer closes a document it tears the JavaScript sandbox down before the event gets there, so the script is dropped. That happens in pdf.js itself, not in this library - the file that dispatches the event is unchanged from Mozilla's code.
  • enableOpenActionJavaScript - the /OpenAction entry. Watch the log: pdf.js runs this one twice, once while the sandbox initializes the document and once for the "Open" event.

Neither flag covers the document-level script in the name tree or the page actions. Those run whenever enableScripting is on - worth knowing if you accept PDF files from strangers.

About the alert boxes: pdf.js only shows app.alert() when you interacted with the document during the last five seconds, and every alert uses that gesture up. Printing and saving explicitly don't count as an interaction (see event.js in pdf.js), so click into the log field first, then press Ctrl+P - otherwise WillPrint writes its line but stays silent. console.println() has no such restriction; look for "PDF.js Console::" in the browser console.

One more thing worth knowing: a script that changes the colour of a field never reaches the printout. pdf.js applies colours to the HTML input element on screen only. Changes to a field's value or visibility do show up, because those go through the annotation storage.
