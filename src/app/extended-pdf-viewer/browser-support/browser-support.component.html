Browser support

The goal of the project is to be compatible with almost every popular browser that's up-to-date. In other words, I frequently run tests on Chrome, Firefox, and Safari on an iPad, and I update all of them pretty soon.

There's also a limited support for older browsers:

  • By default, the library ships binaries compiled to a pretty contemporary JavaScript version. The precise EcmaScript version varies over time, but sometimes even the ESR versions of Firefox are too old to run this code.
  • As a fallback, the library ships a second, transpiled build. It reaches back to roughly Chrome and Edge 80, Firefox 78, and Safari 13.1 (iOS 13.4), which covers most iOS and Android devices that haven't been updated for a few years. Older than that is out of scope.
  • Internet Explorer is not supported. If you need an IE11 version, you can try ngx-extended-pdf-viewer 7.3.2, but without any support from my side.

When the library initializes, it runs a few checks to decide which of the two builds your browser gets:

  • Does the browser support private fields and methods using the # prefix, optional chaining, logical assignment operators, and String.at()?
  • Does it support Promise.withResolvers()?
  • Does it support iterator helpers, such as [].values().map() and .toArray()?

The last check is the one that actually decides. pdf.js 6 calls iterator helpers on Map and Set, and the modern build ships no polyfills - so the modern build needs Chrome/Edge 122, Firefox 131, or Safari/iOS 18.4. Everything below that gets the transpiled build.

If any of these checks fails, the library uses the slower and larger transpiled build.

In case of an emergency, you can force ngx-extended-pdf-viewer to use the transpiled build by setting the attribute [forceUsingLegacyES5]="true".
