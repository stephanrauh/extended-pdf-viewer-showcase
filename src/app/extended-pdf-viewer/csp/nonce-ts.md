```ts
// src/app/app.config.ts
// Hand Angular the nonce your server generated for this
// response. The viewer reads the same CSP_NONCE token and
// stamps it on every <script> and <style> it creates.
import { ApplicationConfig, CSP_NONCE } from '@angular/core';

export const appConfig: ApplicationConfig = {
  providers: [
    { provide: CSP_NONCE, useValue: getNonceFromTheServer() },
  ],
};
```

```html
<!-- src/index.html
     Angular needs the nonce on the root element as well,
     for the styles of your own components. -->
<app-root ngCspNonce="{{ nonce }}"></app-root>
```

```
Content-Security-Policy:
  default-src 'self';
  script-src  'self' 'nonce-{{ nonce }}';
  style-src   'self' 'nonce-{{ nonce }}';
  img-src     'self' data: blob:;
  connect-src 'self' blob: data:;
  object-src  'none'
```

With a nonce you need **no `'unsafe-inline'` at all** - neither for scripts nor
for styles - and you can leave `[useInlineScripts]` at its default. Measured on
a minimal application: loading, rendering, text selection, thumbnails, search,
printing and downloading produce no violation.

The catch is that a nonce has to be a fresh random value for every single
response, so your HTML must be generated by a server (Angular SSR, or a template
rendered by your backend). A purely static `index.html` cannot do this - a
hard-coded "nonce" in a static file is no protection at all, because an attacker
reads it as easily as the browser does. If that is your situation, use
`[useInlineScripts]="false"` and the `'unsafe-inline'` variant on the
*Minimal CSP* tab instead.
